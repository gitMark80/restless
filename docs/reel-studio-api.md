# Private Reel Studio API generation

Live entry: /reel → Gemma & Luke → Generate with my HeyGen API credits.

## Production configuration

- HEYGEN_API_KEY: HeyGen developer key, Production Secret. Never use a VITE_ or NEXT_PUBLIC_ prefix.
- REEL_STUDIO_PASSWORD: owner-chosen passphrase of at least 16 characters, Production Secret. Enter it only in Vercel and the Studio login form. Changing it invalidates sessions and review tokens.
- Existing KV_REST_API_URL and KV_REST_API_TOKEN (Upstash) store only rf:studio:v1:* keys.
- Redeploy after changing environment variables. Setup fails closed until all three requirements are available.

No OpenAI key is used. X-Api-Key requests go to api.heygen.com/v3, using Avatar IV photo avatars at their existing IDs and saved voices. Billing is the developer API wallet, never OAuth. Generation is blocked when HeyGen reports subscription billing. The estimate uses 150 words/minute and the published $2.31/minute rate reviewed 2026-11-09; it is not a quote or a hard spending cap. Recheck pricing before changing engines.

## Owner workflow

1. Unlock the Studio. A Secure, HttpOnly, SameSite=Strict cookie lasts seven days. The password is never saved in localStorage.
2. Paste exact narration or copy the prepared answer. Choose Gemma/Luke and review the exact script and estimated cost.
3. Approve generation. The server validates the signed review and passes the script unchanged. No video is generated by login, account checks, quote, or status actions.
4. Return to Your clips to resume polling. Open/save the MP4 or load it into the current reel, which restores the exact script/question and presenter. Download the sidecar captions to upload through the existing caption control if wanted.

## Persistence and failure behavior

Up to 450 words / 6,000 characters per clip. Five new submission attempts per hour. One Redis NX reservation prevents concurrent/repeated identical presenter+script submissions for 24 hours. Ambiguous errors reserve that request for 90 days and explicitly direct the owner to HeyGen; the app never retries paid POSTs. A provider ID must be recovered manually before resuming an ambiguous job. Do not delete reservations simply because a client timed out.

Jobs contain the exact script, question, source labels, presenter, timestamps and provider status/URLs. Records expire after 90 days; the UI shows the latest 20. The sorted-set index contains job IDs and timestamps only. Finished URLs are refreshed from HeyGen when checking a saved job; download finished media for independent retention. No webhooks or public upload bucket are created.

Authentication is required for all provider/account/job calls. POSTs also require an allowed Origin and JSON. Login attempts use atomic Redis counters. Responses are no-store and provider error bodies are not sent to browsers. Unknown job IDs cannot be used to probe arbitrary HeyGen resources.

## Validation

Run npm test and npm run build. Also syntax-check the inline module in public/reel/index.html: Vite copies public files without parsing their scripts.

Tests mock the external services and verify authentication, CSRF, rate limits, exact script preservation, signed reviews, concurrent submissions, uncertain results, job ownership, and server-side credentials. Live paid generation is a separate owner action; never create extra videos as an automatic deployment test.
